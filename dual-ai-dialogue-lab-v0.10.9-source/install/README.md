# 双 AI 对话实验室 v0.10.8

## 安装 / 更新

1. `chrome://extensions`（Chrome）或 `edge://extensions`（Edge）→ 停用或删除旧版（0.10.7 及更早）。
2. 开启「开发人员模式」→「加载解压缩的扩展程序」→ 选择解压后的目录（目录内应直接可见 `manifest.json`）。
3. **刷新已打开的 ChatGPT 与 DeepSeek 网页**（内容脚本不会热更新，不刷新还是旧代码）。
4. 打开侧栏，确认版本为 0.10.8。

## 本版修了什么

v0.10.7 的真机诊断显示：附件卡片被识别到了，文件名也读到了，但仍然判 0/N。

```json
{ "tag": "button", "text": "A题(20261019-123948).pdf", "matchedName": "" }
"counts": { "A题.pdf": 0 }
```

原因：文件名别名的规则只接受**空格分隔**的时间戳 `A题(20261019 123948).pdf` 和纯数字后缀 `A题(4).pdf`，而 ChatGPT 实际生成的是**连字符分隔**的 `A题(20261019-123948).pdf`，两边都对不上。

本版改动：

- 别名后缀支持 `20261019-123948`、`20261019 123948`、`20261019_123948`、`20261019123948`、只带日期、只带时间、纯序号；
- 卡片识别排除侧边栏历史项与「添加文件」按钮（v0.10.7 的 `cardCount=4` 里有 2 个是误报）；
- 词干匹配允许后面跟 `(`，覆盖「带别名 + 扩展名被截断」的卡片名。

**仍是同一原则：只有全部文件都有独立证据、且没有上传中/失败提示时才判定成功**，没有新增跳过验证的路径。

## 出问题时怎么反馈

复现后导出「自动诊断」，找第一条 `阶段=verify-unconfirmed`，把它的完整详情贴回来。重点看：

| 字段 | 看什么 |
|---|---|
| `counts` | 每个文件的整页匹配次数；本版修复后 `A题.pdf` 应为 1 而不是 0 |
| `attachmentCards[].text` | 卡片上真实显示的文件名（这是最关键的一手数据） |
| `attachmentCards[].matchedName` | 是否被识别成目标文件；为空说明名称形式仍未被覆盖 |
| `cardCount` | 真实卡片数量（排除侧边栏与上传按钮后） |
| `cardPresentNoName` | 卡片在但名称读不出的文件 |
| `scopeBox.degraded` | `true` 表示局部范围退化、走了全页扫描 |
| `failureClass` | 见下表 |

| 分类 | 含义 |
|---|---|
| `page-upload-error` | 网页明确报上传失败/格式不支持 |
| `upload-still-busy` | 仍在上传或处理中 |
| `attachments-vanished-after-upload` | 曾出现证据，最终既无匹配也无卡片 |
| `initial-evidence-disappeared` | 曾出现证据，最终无匹配但仍有卡片 |
| `card-present-name-unreadable` | 卡片数够但读不出文件名 |
| `card-present-unmatched` | 有卡片但名称与目标不一致 |
| `filename-not-detected` | 没有卡片也没有文件名证据 |
| `stability-timeout` | 已匹配但未稳定确认 |

## 人工确认

自动核验未通过时侧栏会暂停：先确认网页输入区里**全部附件卡片都在、文件名正确、无上传中/失败提示**，再勾选确认框点「人工目视确认」。该记录会标记为「人工目视确认（自动检测漏报）」。
