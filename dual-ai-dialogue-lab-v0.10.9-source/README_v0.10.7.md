# 双 AI 对话实验室 v0.10.7

## 安装 / 更新

1. 在 `chrome://extensions`（Chrome）或 `edge://extensions`（Edge）中，先**停用或删除**旧版本（0.10.6 及更早）。
2. 打开右上角「开发人员模式」。
3. 点「加载解压缩的扩展程序」，选择解压后的目录（目录里应直接能看到 `manifest.json`）。
4. **刷新已打开的 ChatGPT 与 DeepSeek 网页**。内容脚本不会热更新，不刷新就还是旧代码在跑。
5. 打开侧栏（点扩展图标），确认版本显示为 0.10.7。

## 本版修了什么

「附件卡片明明还在输入区，扩展却判定 0/N 并中止发送」。

两个根因：

1. **局部检测范围会退化成空集**。旧实现以输入框的视口矩形为基准，向上 760px、向下 180px。输入框滚出视口或页面未完成布局时，这个矩形可能变成空集，于是一切局部证据与诊断节点都被跳过 —— 这就是「卡片还在，`evidenceByName`/`localEvidenceByName`/`diagnosticNodes` 却全空」的原因。
2. **只认文件名文本**。卡片把名字截断、名字只放在读不到的属性里、或文本节点被拆开时，卡片存在也会被判成 0/N。

现在的做法：

- 局部范围改为「沿输入框向上 6 层祖先的包围盒并集」；若并集高度 < 80px 则标记退化，退回全页扫描但只接受带附件语义的节点。
- 新增第 4 条证据通道：**附件卡片结构化识别**（文件/附件语义属性、几何尺寸上界、移除按钮、最近内层去重），并对卡片做文件名与**词干**匹配（支持 `A题.pd…` 这类截断）。
- 把「卡片在但名字读不出」与「根本没有卡片」分成不同失败分类，不再只报 `initial-evidence-disappeared`。
- 诊断采样改为按优先级（文件名匹配 > 附件卡片 > 上传状态 > 其他），不再被侧边栏历史文字挤占。
- 诊断不再 `slice(0, 7000)` 一刀切：结论字段永不丢弃，明细按预算追加，且输出始终是**合法 JSON**。

**没有新增任何「跳过验证直接发送」的路径**：`confirmed` 仍然只在「全部文件都有独立证据 + 无上传中状态 + 无失败提示」时为真。

## 出问题时怎么反馈

1. 复现问题后，在侧栏导出「自动诊断」。
2. 找到第一条 `阶段=verify-unconfirmed` 的记录，把它的**完整详情**贴回来（现在上限 12000 字符，不会被截掉关键部分）。
3. 重点看这几个字段，它们能直接说明问题出在哪一环：

| 字段 | 含义 |
|---|---|
| `failureClass` | 失败分类，见下表 |
| `failureDetail` | 判定依据：卡片数、缺失文件、不可读名称、即时证据有无、最后匹配 |
| `attachmentCards` | 检测到的附件卡片：文本、属性、坐标、是否匹配到文件名 |
| `cardPresentNoName` | 卡片存在但读不出名字的文件 |
| `scopeBox` | 本次使用的局部范围；`degraded:true` 表示退化到全页扫描 |
| `diagnosticNodes[].matchReason` | 每个诊断节点为什么被采到（`filename`/`file-semantics`/`upload-state`/`near-composer`） |
| `verificationHistory` | 最近 10 次采样的匹配/卡片数/忙碌状态 |
| `nativeFileInputState` | 原生 `input[type=file]` 的 FileList 内容（为空不代表网页没接受文件） |

失败分类速查：

| 分类 | 含义 | 处理 |
|---|---|---|
| `page-upload-error` | 网页明确提示上传失败/格式不支持 | 换文件或检查格式 |
| `upload-still-busy` | 仍在上传/处理中 | 等完成后点「重新检查」 |
| `attachments-vanished-after-upload` | 曾出现证据，最终既无匹配也无卡片 | 多半真的被网页移除了 |
| `initial-evidence-disappeared` | 曾出现证据，最终无匹配但仍有卡片 | 检测器漏检，可用人工确认 |
| `card-present-name-unreadable` | 卡片数量够，但读不出文件名 | 目视核对文件名后人工确认 |
| `card-present-unmatched` | 有卡片，但名称与目标文件不一致 | 可能传错文件，先核对 |
| `filename-not-detected` | 没有卡片，也没有文件名证据 | 网页可能没接受文件，重新投递 |
| `stability-timeout` | 已匹配但未能稳定确认 | 通常再点一次重新检查即可 |

## 人工确认

自动核验未通过时，侧栏会暂停并请求人工核对：

- 先在网页上确认**全部附件卡片确实存在、文件名正确、没有「上传中」或失败提示**；
- 再勾选侧栏的确认框并点「人工目视确认」继续。

该记录会明确标注为「人工目视确认（自动检测漏报）」，不会被伪装成自动检测成功。
